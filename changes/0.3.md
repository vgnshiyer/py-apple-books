# Stream 0.3: bookinfo-ddl

Release-notes fragment for stream 4.2 to assemble. Testing package
only (`py_apple_books.testing`): no change to the library's API or
output.

## CHANGELOG

### Added

- **Schema reports include Books' book-info cache.**
  `python -m py_apple_books.testing.dump_schema` also writes
  `AEBookInfo.sql` when Books keeps per-book info caches next to the
  library (`Library/Caches/AEEpubInfoSource` in its container): the
  `CREATE TABLE` and `CREATE INDEX` statements of the newest cache's
  `ZAEBOOKINFO` table, never a row, and with no string or blob literal,
  quoted name or comment, checked for that before it's saved.
  `meta.json` records the cache's file name and column count
  (`"book_info"`), and `--compare` reports its column differences. The
  cache is opened read-only according to its journal mode and is never
  written. Every file SQLite may open beside it (`-journal`, `-wal`,
  `-shm`) is checked first: files that are only in iCloud, symlinks and
  FIFOs are never opened, and a cache in a cloud-storage folder, or in
  rollback-journal mode with a non-empty `-wal` file beside it, is
  refused. No file is created beside the cache unless Books changes it
  during the read, which is reported (for a WAL cache, SQLite may
  update its shared-memory index, the `-shm` file, as any reader
  does). Without such a cache, or when it is refused or unreadable,
  the report is the same as before, plus a note on stderr. The
  committed macOS 26.7 / Books 8.5 schema fixture now includes
  `AEBookInfo.sql`, so test caches can be built from Apple's own table
  definition.

### Changed

- **Schema reports check the schema text they copy before running it.**
  `dump_schema` refuses a store whose schema entries are anything but
  single `CREATE` statements without comments, and its self-check runs
  the generated SQL so that it can only build the schema and its
  bookkeeping rows: it can no longer attach another database, create a
  file or a temporary table. The committed macOS 26.7 / Books 8.5
  schemas pass unchanged. A store these checks refuse, such as one with
  an index on a function call (which 1.10 dumped), ends the dump with an
  error that asks you to report it on the issue tracker.
