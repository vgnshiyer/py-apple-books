# Stream 3.2: chapter-spans

Release-notes fragment for stream 4.2 to assemble. Changes
`BookContent.get_chapter` (new keyword arguments; the default text is
unchanged) and adds the private `py_apple_books/_spans.py`.

## CHANGELOG

### Added

- `BookContent.get_chapter(chapter_id, *, span='file', normalize_unicode=False)`.
  `span='file'` (the default) returns the same text as 1.10, through the
  same id lookup: the entry's own file, from its fragment to where another
  entry of that file begins. Two opt-in modes follow the book's reading
  order (its spine, without entries marked `linear="no"`) across files:
  - `span='section'`: from where the entry begins up to where the next
    table-of-contents entry of any depth begins, so a chapter split over
    several files comes back whole;
  - `span='chapter'`: up to the next entry of the same depth or shallower,
    so a part includes its chapters and a chapter its sections.

  In both modes `chapter_id` is looked up as a chapter's order (`"5"`,
  ASCII digits without leading zeros) first, then as a chapter id, then
  as a manifest id (a file in the reading order spans from its start to
  the next entry; another text file gives its whole text; an image or
  other binary file raises `ChapterNotFoundError`). Fragments are matched
  by `id`, then by `<a name>`. An entry with no text of its own (an image
  page, a part heading whose first chapter begins at the same place)
  gives `""`. Each file is read at most once per call, from the book
  already loaded, so a spine that lists a file many times costs nothing
  extra. A bad `span` raises `InvalidChoiceError` before anything is read.
- `normalize_unicode=True` on `get_chapter` removes soft hyphens,
  zero-width spaces and byte-order marks and composes accents, then tidies
  the whitespace again (as on `get_spine_item_text`).

### Notes

- A location's `chapter_id` (`Location.chapter_id`) names the file the
  location is in. In books whose converter split chapters across files
  (Calibre's `index_split_NNN` files) that file's id can also be the id of
  the next chapter, which begins later in the file, so
  `get_chapter(location.chapter_id, span=...)` can return the next
  chapter. Read a location's own file with `get_spine_item_text`, or find
  its chapter first and pass that chapter's order with `span`.
