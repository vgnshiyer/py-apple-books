# Stream 2.4: metadata

Release-notes fragment for stream 4.2 to assemble. New methods and
types only: no existing method's results change.

## CHANGELOG

### Added

- **`get_book_metadata(book_id, *, read_files=True)`** returns a
  `py_apple_books.models.BookMetadata`: language (a normalised BCP 47
  tag such as `en-US`), publisher, publication date (`published`,
  `'YYYY'`, `'YYYY-MM'` or `'YYYY-MM-DD'`, and `year`), ISBN
  (checksum-verified; an ISBN-13 when the book has one), subjects,
  description (plain text), the cover image's path inside the book, and
  a series named in the book file (calibre or EPUB 3
  `belongs-to-collection`; `series_title`, `series_sequence`).
  - What the library records comes first (language, the Store release
    date or year, description, genre as the first subject); the book's
    own package document (OPF) fills in the rest, and `book_file_fields`
    says which fields came from it. Every text value is untrusted text
    from the library or the book file.
  - Only `META-INF/container.xml` and the package document are read,
    from an unzipped EPUB that is on this Mac. A book stored only in
    iCloud, or partly evicted, is never downloaded: `file_state` reports
    it as `not_downloaded` (open the book in Apple Books, then try
    again). `file_state` (`py_apple_books.models.MetadataFileState`) is
    one of `read`, `not_requested` (`read_files=False`: library values
    only, no file access), `no_file`, `not_epub`, `not_downloaded` and
    `unreadable`; file problems never raise. DRM doesn't matter here:
    package documents aren't encrypted.
  - The package document is treated as untrusted input: a DOCTYPE with
    an internal subset (entity declarations) is refused, external
    entities are never fetched, and parsing is bounded (file size,
    elements, depth, text lengths) and stops once the needed parts are
    read. Symlinks inside the book folder are refused.
  - Results read from book files are cached in memory, bounded, while
    the two files are unchanged; `py_apple_books.content.clear_content_cache()`
    empties the cache.
- **`get_series(book_id)`** and **`list_series(*, started_only=False,
  limit=None, offset=None)`** (provisional): the Apple Books Store
  series the library records, as `py_apple_books.models.Series` (title,
  `series_id`, the series `container` row, `is_ordered`, `volumes`) of
  `SeriesVolume`s (`book`, `ids`, `sequence`, `label`, `in_library`,
  `reading_status`).
  - `get_series` accepts a volume, the series container, or a copy of a
    volume in your library that shares only its Store id; None when
    Books records no series for the book. `volumes` are the volumes
    Books knows about, owned or not, never the length of the series.
  - `Series.volume_for(book_id)`, `next_after(book_id)`, `current` (the
    volume in progress with the highest sequence) and `up_next` (the
    volume after the furthest one started or finished).
  - `SeriesVolume.in_library` follows `list_books()`'s rule exactly
    (Store series rows you don't own stay out of every list, as in
    1.10).
  - Library database only (`get_series` at most 4 statements,
    `list_series` at most 2); no book file is opened. `list_series`
    returns a list, ordered by title, with `offset` and `limit` applied
    in Python; `limit` must be at least 1 and `offset` at least 0
    (`InvalidArgumentError` otherwise).
  - Provisional: `get_series`, `list_series`, `Series` and
    `SeriesVolume` may change in 1.12, once a library with bought Store
    series books has been checked.

### Compatibility notes

- `py_apple_books.models` exports four more names: `BookMetadata`,
  `MetadataFileState`, `Series`, `SeriesVolume`.
- `Series` and `SeriesVolume` are frozen but not hashable (they hold
  `Book` models, which aren't); `BookMetadata` is frozen and hashable.

| `get_book_metadata(book_id, *, read_files=True)` | `BookMetadata`: language, publisher, publication date, ISBN, subjects, description, cover path and series from the library, completed from the book's package document; never downloads an iCloud book (`file_state`) |

- "Model data": add `BookMetadata`, `MetadataFileState`, `Series` and
  `SeriesVolume` (import from `py_apple_books.models`), with the field
  lists above; mark the series types provisional.
- "Pagination and counting": `list_series` returns a list; `offset` and
  `limit` are applied in Python after ordering.
- "How content access handles Apple Books' quirks": add a paragraph:
  "`get_book_metadata` reads only `container.xml` and the package
  document. It checks, in order and without touching the disk for the
  first three: a file recorded, an `.epub` path, Books not recording the
  book as stored only in iCloud; then that the book folder is on this
  Mac with no iCloud stub next to it, that every folder and file in it
  is on this Mac (each folder checked before it is listed, as
  `get_book_content` checks), `is_downloaded`, and every folder and
  file on the way to the package document, each before anything inside
  it is looked up or read. Anything not on this Mac, including a partly
  evicted book, is reported as `not_downloaded`, never downloaded."
