# Stream 2.1: content-index

Release-notes fragment for stream 4.2 to assemble. A process-wide index
of each book's table of contents and spine, read from a few small files;
a spine API on `BookContent`; `Chapter.spine_index`. Existing methods
return the same values as in 1.10.

## CHANGELOG

### Added

- `BookContent.list_spine_items()`: the book's spine (its reading order
  as the package document lists it) as `SpineItem` entries: `index`
  (0-based, the same number as `Location.spine_index`), `item_id`,
  `href` (relative to the book folder, like `Chapter.href`),
  `media_type`, `linear` (False for entries marked `linear="no"`, such
  as notes), `is_toc_page` (the navigation document, or a page the
  book's guide or landmarks name as its table of contents), `readable`
  (the entry names a document with text: not an image, stylesheet,
  font, audio, video or script) and `toc_orders` (the `Chapter.order`
  of the table-of-contents entries in that file).
- `BookContent.get_spine_item_text(item, *, normalize_unicode=False)`:
  the plain text of one whole spine file, by manifest id (`str`, such
  as `Location.chapter_id`) or spine index (`int`, such as
  `Location.spine_index`). The same text `get_chapter()` gives for a
  file that holds one chapter, extracted the same way, never cut at a
  table-of-contents entry. Images, stylesheets, fonts and other binary
  files raise `ChapterNotFoundError`. `normalize_unicode=True` removes
  soft hyphens, zero-width spaces and BOMs and composes accents.
- `BookContent.iter_spine_text(*, start=None, until=None,
  include_nonlinear=False, include_toc_pages=False)`: the book's text
  one spine item at a time, as `SpineText` slices (`index`, `item_id`,
  `offset`, `text`, `length`, `readable`, with `position`, `end` and
  `complete`), from a `TextPosition` up to a `TextPosition` or a
  `ResolvedBoundary` (exclusive). Non-linear items and
  table-of-contents pages are left out unless asked for; an item whose
  text can't be read is reported once with `readable=False`. Each item
  is read when the iteration reaches it. A `ResolvedBoundary` resolved
  for another book raises `InvalidArgumentError` on a `BookContent`
  from `get_book_content()`; one made from a path alone can't tell
  which book a boundary belongs to.
- `Chapter.spine_index`: the 0-based spine position of the chapter's
  file (None when the file isn't in the spine). It is not part of
  equality, hashing or `repr`, so chapters compare and print as before.
- `py_apple_books.content` also defines `TextHit`, `TextSearchResult`,
  `MAX_SEARCH_HITS` and `MAX_SNIPPET_CONTEXT`, the result types of the
  book-text search added in this release.

### Changed

- **`list_chapters()` is cached.** A `BookContent` computes its chapter
  list once, and the list is kept process-wide, keyed by the size and
  modification time of the book's `container.xml`, package document and
  navigation files, so a repeat call on any instance (including a new
  one from `get_book_content()`) reads only file metadata instead of the
  whole book. `get_current_reading_chapter()` benefits too. The values
  are unchanged: the first call on a book still reads it the 1.10 way
  (with the same errors), and the cached list is used only after it
  matched that read. Later calls reuse the list while `container.xml`,
  the package document and the navigation files are unchanged, so a
  chapter file that has since gone missing or become unreadable is
  reported by `get_chapter()` rather than by `list_chapters()`. Each
  call returns a new list; the `Chapter` objects in it are shared (they
  are immutable). Call `content.clear_content_cache()` after changing a
  book's files in place.
- The new spine methods read only the book's `container.xml`, package
  document and navigation files, then each file whose text is asked for,
  each checked first not to be stored only in iCloud (nothing is
  downloaded) and never through `du` or a walk of the book folder. They
  refuse DRM-protected books (`DRMProtectedError`) and books stored
  partly in iCloud (`BookNotDownloadedError`).

### Compatibility notes

- `dataclasses.fields(Chapter)`, `asdict()` and `astuple()` include the
  new `spine_index` field (last). A `Chapter` pickled by 1.10 loads with
  `spine_index` None.
- The process-wide cache holds at most about 32 MiB (estimated) and
  4,096 entries, in memory only, and is never written to disk.
- On a library whose books are fully downloaded, apple-books-mcp 0.8.2
  and 0.9.0 output is unchanged.

## README

- Book Content table, `BookContent` methods: rows for
  `list_spine_items()` (`list[SpineItem]`),
  `get_spine_item_text(item, *, normalize_unicode=False)` (`str`) and
  `iter_spine_text(*, start, until, include_nonlinear,
  include_toc_pages)` (`Iterator[SpineText]`); the `list_chapters()`
  row notes that `Chapter.spine_index` (v1.11.0+) gives the chapter's
  spine position. Below the table: "Import `SpineItem`, `SpineText` and
  `Chapter` from `py_apple_books.content`. Offsets in
  `get_spine_item_text()` text are the offsets of
  `py_apple_books.positions.TextPosition`; they are not offsets into
  `get_chapter()` text."
- "How content access handles Apple Books' quirks": a bullet "**Caches
  and memory** — chapter lists and spines are kept in memory,
  process-wide, keyed by file sizes and modification times (at most
  about 32 MiB); `content.clear_content_cache()` drops them. Only each
  book's table of contents (chapter titles and its navigation files)
  and the positions of the anchors in its chapter files are kept
  process-wide; chapter text is not cached across `BookContent`
  instances, and nothing is written to disk." and, in the iCloud
  bullet, that the spine methods check each file before reading it
  instead of running `du`.
- Testing docs: call `content.clear_content_cache()` between tests that
  rewrite a book folder in place.
