# Stream 1.1: content safety

Release-notes fragment for stream 4.2 to assemble. Reading a book never
downloads a file macOS has moved to iCloud; error messages stay short;
new exception classes; `BookContent` gains `book_id`, thread safety and
pickling.

## CHANGELOG

### Added

- `PyAppleBooks.get_book_content()` also accepts a `Book`. A book read
  from the same library is used as is, with no query (unless its `path`
  or `state` wasn't read); a book from another library is looked up by
  id.
- `BookContent(path, *, book_id=None)` and a read-only `book_id`
  property; `get_book_content()` sets it.
- `py_apple_books.content.clear_content_cache()`: drops everything the
  library has cached from book files (call it after changing a book's
  files in place).
- `NotEpubError` (an `AppleBooksError`): raised by the chapter methods
  of `BookContent` for a PDF or any other non-EPUB file, with the same
  messages as before.
- `ContextUnavailableError(message, reason=None, annotation_id=None)`
  (an `AppleBooksError`), with reason constants `NO_LOCATION`,
  `NO_HIGHLIGHT_TEXT`, `ORPHANED`, `EMPTY_CHAPTER` and
  `HIGHLIGHT_NOT_FOUND`, for the annotation context API added in this
  release.
- `UnsafeEpubEntryError.entry`: the full entry name the book used
  (the message may shorten it).

### Changed

- **No read downloads an iCloud file.** Books in iCloud Drive can be
  partly or wholly moved to iCloud by macOS. Every read of a book's
  files now checks each folder and file first and never looks inside
  one that is only in iCloud, and reads run with downloads of such
  files turned off for the reading thread (macOS only), so anything
  missed fails instead of being downloaded. Such reads raise
  `BookNotDownloadedError`: "Part of this book is stored only in
  iCloud. Open it in Apple Books to download it, then try again."
  Books that are fully on disk read exactly as before.
- **`get_book_content()` refuses iCloud books up front.** A book Apple
  Books records as stored only in iCloud is refused before any of its
  files is touched, and a book whose file or folder is itself only in
  iCloud is refused before the download check runs, both with the
  existing "stored in iCloud" message. A book with only some of its
  files in iCloud is refused with the message above.
- `content.is_downloaded()` and `BookContent.is_downloaded` report a
  file or folder that is itself only in iCloud (or has an iCloud stub
  next to it) as not downloaded without running `du`.
- `BookContent` can be shared between threads (the book is read once)
  and can be pickled or copied.

### Fixed

- Error messages about a book's files shorten the names of files inside
  the book, and the book's file name, when longer than 80 characters (to
  their first 60 and last 20 characters), and operating-system errors in
  them name only a file's base name, never its path. Names of up to 80
  characters read as before. Book titles in `get_book_content()`
  messages are unchanged.
- `BookContent.is_drm_protected` no longer looks inside a book folder
  that is only in iCloud; it reports such a book as protected (it can't
  be read either way) and never raises.

### Compatibility notes

- `NotEpubError` is a new subclass of `AppleBooksError`; code that
  catches `AppleBooksError` keeps working.
- The behaviour changes above only show on books stored partly or
  wholly in iCloud: on a library whose books are fully downloaded,
  apple-books-mcp 0.8.2 and 0.9.0 output is unchanged.

## README

- Reading book content: a note that books stored only in iCloud, or
  partly in iCloud, are refused with `BookNotDownloadedError` and are
  never downloaded by the library; open them in Apple Books first.
- API reference rows: `get_book_content(book_id | Book)`,
  `BookContent.book_id`, `content.clear_content_cache()`, and the new
  exceptions `NotEpubError` and `ContextUnavailableError` in the
  exception tree.
