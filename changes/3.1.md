# Stream 3.1: positions

Release-notes fragment for stream 4.2 to assemble. Where the reader is,
where each annotation is, and a structured context for a highlight:
`BookContent.resolve`, `PyAppleBooks.get_reading_position`,
`get_annotation_locations` and `get_annotation_context`. No existing
method changes; apple-books-mcp 0.8.2 and 0.9.0 output is unchanged.

## CHANGELOG

### Added

- `BookContent.resolve(location)`: where a location is in the book, as
  a `ResolvedLocation` (from `py_apple_books.positions`): its spine
  file (`spine_index`, `item_id`) and the table-of-contents entry it
  belongs to (`chapter`), with `match` saying how that entry was chosen:
  `file` (the file holds one entry), `anchor` (the file holds several;
  the last one starting at or before the location, compared with where
  each entry's anchor is in the file), `preceding` (the file holds none,
  or the location is before all of them: the last entry earlier in the
  book), `front_matter` (no entry starts before it) or
  `section_unknown` (the file holds several entries but where they
  start couldn't be read; no chapter is guessed). `location` is a
  `Location` (such as `annotation.location`), a CFI string, or a spine
  index (`int`, the start of that file). Returns None when the location
  names no file of this book; a malformed CFI never raises (one whose
  spine step names a file but whose path inside it is malformed gives
  that file, `section_unknown` when it holds several entries). Reads only
  the book's index and, for a file holding several entries, where its
  anchors are (both cached).
- `PyAppleBooks.get_reading_position(book_id, *, resolve_chapter=True,
  infer=True)`: where the reader is, as a `ReadingPosition`: from Apple
  Books' reading-position bookmark (its CFI, or its page data: the page
  of a PDF, the spine file of an EPUB), else inferred from the newest
  highlight or bookmark with a location (`source='recent_annotation'`),
  with the chapter (`chapter`, `match`, `total_chapters`) when asked
  for. Also the position as a fraction of the book (`fraction`), the
  furthest point read (`furthest_fraction`), and for PDFs the page and
  page count (`page`, `page_count`; `page_count_estimated` when the
  count is worked out from the page and the fraction). When the book
  can't be read (not downloaded, DRM-protected, a PDF) the position is
  still returned, with the reason in `unavailable`. At most three
  queries (two for a `Book` that has a file here);
  `resolve_chapter=False` touches no file. `book_id` may be a `Book`.
  Returns None when nothing records a position.
- `PyAppleBooks.get_annotation_locations(annotations)`: the spine file
  and chapter of many annotations at once, as `{annotation.id:
  ResolvedLocation}`: each book is looked up once (one query) and read
  once. An annotation that can't be placed says why in `unavailable`
  (`no_location`, `orphaned`, or its book's reason such as
  `not_downloaded`, `drm`, `not_epub`).
- `PyAppleBooks.get_annotation_context(annotation_id, chars_before=300,
  chars_after=300)`: a highlight with the text around it, as an
  `AnnotationContext` (`before`, `highlight`, `after`, whether the text
  was cut at either end, the chapter, and the spine file). `str()` of it
  is exactly the text `get_annotation_surrounding_text()` returns
  whenever that finds the highlight, unless the highlight occurs
  several times and the context took another occurrence than the first
  (`disambiguated`, below). It also finds highlights that
  method doesn't: across soft hyphens and zero-width spaces, and with
  different case, accents, quotes or dashes (`text_match` says which:
  `exact`, `whitespace`, `invisible`, `folded`; `exact` when the
  occurrence found is verbatim the highlight); of several occurrences
  it takes the one inside the annotation's surrounding passage when
  that passage occurs once (`disambiguated`), and reports how many there
  are (`occurrences`). Instead of an empty string it raises: a
  `ContextUnavailableError` whose `reason` says what is missing
  (`no_location`, `no_highlight_text`, `orphaned`, `empty_chapter`,
  `highlight_not_found`), or the error the book raises
  (`BookNotDownloadedError`, `DRMProtectedError`, `NotEpubError`...).
  It never returns the chapter opening in place of a highlight it can't
  find. Accepts an `Annotation` as well as an id.

### Changed

- `get_annotation_surrounding_text()`, `get_current_reading_chapter()`
  and `get_current_reading_location()` are superseded by
  `get_annotation_context()` and `get_reading_position()`. They are
  unchanged and not deprecated (no warning).

### Compatibility notes

- These methods never run `du` or walk a book folder, and never
  download a file stored only in iCloud: a book or file that isn't on
  this Mac is reported as `not_downloaded`.
- A location in a file holding several table-of-contents entries is
  placed by comparing its CFI with the entries' anchors. Where that
  can't be done, `section_unknown` is given, never the file's first
  entry.

## Integrator notes (not for the CHANGELOG)

- `tests/test_spine_api.py::TestMixins::test_book_content_bases` (owned
  by 2.1) fails on this branch, on 3.10 and 3.14 (the only failure of
  the full suite): it asserts that `_ResolveMixin` and `_ReadingMixin`
  define no names, and this stream adds `resolve` to `_ResolveMixin`.
  At merge, replace it with the version below, which matches 3.3's
  (changes/3.3.md, "Integrator notes") plus a public-names check for
  `_ResolveMixin`. Merge 3.1 before 3.3 with this replacement applied;
  with 3.1 alone merged, drop the `_ReadingMixin` public-names line
  until 3.3 lands.

  ```python
  def test_book_content_bases(self):
      assert BookContent.__bases__ == (_ResolveMixin, _ReadingMixin)
      for mixin in (_ResolveMixin, _ReadingMixin):
          assert "__init__" not in vars(mixin)
          assert vars(mixin).get("__slots__") == ()
      public = {n for n in vars(_ResolveMixin) if not n.startswith("_")}
      assert public == {"resolve"}
      public = {n for n in vars(_ReadingMixin) if not n.startswith("_")}
      assert public == {"search", "resolve_boundary", "position_at_percent"}
  ```

- The spec's real-library check "`str(ctx)` vs wrapper: 0 mismatches"
  conflicts with the disambiguation the spec also requires (the
  wrapper always takes the first occurrence). Read it as 0 mismatches
  among contexts with `disambiguated=False`.
- R18 says the tiers try "exact, then whitespace-flexible". There is no
  separate exact pass: `text_match='exact'` means the occurrence the
  1.10 whitespace-flexible pattern finds first is verbatim the
  highlight. An exact-first pass would pick a later verbatim occurrence
  and break `str(ctx)` == wrapper; R18 may want that wording amended.
  Pinned by `test_exact_means_the_first_whitespace_match_is_verbatim`.
- The spec's statement budget "2 with a Book" holds for a Book that has
  a path, content type and state; a Book with no file here (NULL path)
  is read again by id, so 3 (`test_budget_for_a_book_with_no_file`).
- A file whose ToC entries' anchor paths together exceed
  `_content_resolve._MAX_START_STEPS` (1,000,000 element steps: a
  crafted file of many deeply nested ToC anchors) is `section_unknown`,
  like a file whose anchors can't be read. No real book is expected
  near it; the real-library pass can count files where it applies.
- The F17 PDF tests use page 41 of 120 in place of the plan's figures,
  whose origin (synthetic or not) couldn't be confirmed.
