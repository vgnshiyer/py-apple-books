# Stream 3.3: reading-boundary

Release-notes fragment for stream 4.2 to assemble. Spoiler-safe reading:
how far a book has been read (from the library database alone), that
boundary placed in the book's text, and a search of the book's text that
stops at it. No change to any existing method or its output.

## CHANGELOG

### Added

- **`PyAppleBooks.get_read_boundary(book_id, *, basis='position')`**: how
  far a book has been read, as a `ReadBoundary`, from the library database
  alone (no book file is read; at most three statements). `book_id` takes
  an id or a `Book`. The boundary is placed by the first source the
  library has: Apple Books' reading-position bookmark (the earliest one if
  a book has several, so the boundary is never past any of them; this
  differs on purpose from `get_reading_position`, which reports the
  newest), else the newest highlight, note or bookmark with a location in
  the book's text, else the reading progress, else nothing (`source` is
  `reading_position`, `recent_highlight`, `progress` or `none`).
  `basis='furthest'` (any case) uses the furthest point read when it is
  past the reading progress (`source` `furthest`). Every source found is
  kept on the result. On an older or newer Books database a missing
  column skips the sources that need it and adds the
  `schema_missing_columns` warning; without an annotation store the
  bookmark and highlight are skipped (`annotations_unavailable`). It never
  raises `UnsupportedSchemaError`; an unknown `basis` raises
  `InvalidChoiceError` before any query.
- **`BookContent.resolve_boundary(boundary, *, precision='item')`**: places
  a `ReadBoundary` in the book's text as a `ResolvedBoundary`, at the start
  of the spine item the boundary falls in, never later than the point it
  stands for. A bookmark whose file id and spine step disagree uses the
  earlier item (`bookmark_index_mismatch`); a bookmark in a non-linear
  item (`bookmark_nonlinear`), on a table-of-contents page
  (`bookmark_toc_page`) or not found in the book (`bookmark_unresolved`)
  falls back to the highlight, then the progress, then the start of the
  book, never past the bookmark's own item. `furthest` gives the later of
  the reading position and the furthest point read. `precision='exact'`
  raises `InvalidChoiceError` (only `'item'` is accepted in this release).
  A boundary for another book raises `InvalidArgumentError` on a
  `BookContent` from `get_book_content()`. Results are remembered by the
  instance.
- **`BookContent.position_at_percent(percent)`**: the start of the linear
  spine item that holds that share of the book's linear text, as a
  `TextPosition` (values outside 0 to 100 are clamped; None, booleans,
  NaN and non-numbers raise `InvalidArgumentError`).
- **`BookContent.search(query, *, start=None, until=None, limit=20,
  chars_before=80, chars_after=80, count_total=False, count_withheld=False,
  include_nonlinear=False, include_toc_pages=False)`**: searches the book's
  text in reading order, folded like every search of the library (case,
  accents, typographic quotes and dashes, ligatures and line breaks don't
  matter), and returns a `TextSearchResult` page of `TextHit`s (start and
  end positions, the item's manifest id, and a one-line snippet). With
  `until` (a `TextPosition` or a `ResolvedBoundary`), text from that point
  on is cut off before matching: no match runs across it and no snippet
  shows anything past it. Pass `next_start` back as `start` for the next
  page; `limit=None` gives `MAX_SEARCH_HITS` (1,000), the most any page
  holds. `count_total` counts every match in scope; `count_withheld`
  counts the matches past the boundary, in its own item and in later
  items, without returning them. Non-linear items (such as notes) and
  table-of-contents pages are left out unless asked for. The query is
  converted as `fold_for_match` converts its input (None finds nothing,
  bytes are decoded as UTF-8, other objects go through `str()`). A query
  that folds to nothing finds nothing; one longer than 1,000 characters
  after folding, or 64,000 before, raises `InvalidArgumentError` (the
  message never repeats the query). A match made very long by characters
  that fold to nothing (over 4,000 characters) keeps 2,000 from each end
  in its snippet, joined by an ellipsis. Arguments are checked before
  the book is read.

### Compatibility notes

- `get_read_boundary` and `get_reading_position` can name different
  bookmarks for a book with several live reading-position rows: the
  boundary takes the earliest (spoiler-safe), the position the newest.
- A `ResolvedBoundary` is valid for one book file and one library version,
  like a `TextPosition`.
- Known limitation: a newest highlight on a non-linear item or a
  table-of-contents page falls back to the progress (never later than
  that item's start) without a warning code of its own, so the result
  looks like a placement at a linear highlight.

## README

- In "Positions and reading boundaries (v1.11.0+)", after the types
  table, a short "Spoiler-safe search" example:

  ```python
  boundary = api.get_read_boundary(book_id)
  content = api.get_book_content(book_id)
  read = content.resolve_boundary(boundary)
  result = content.search("captain", until=read, count_withheld=True)
  for hit in result.hits:
      print(hit.start, hit.snippet)
  print(result.withheld_in_item, result.withheld_later, "matches later in the book")
  ```

- Facade methods table: a row for `get_read_boundary(book_id, *,
  basis='position')` (`ReadBoundary`; database only).
- Book Content table, `BookContent` methods: rows for
  `search(query, *, start, until, limit, chars_before, chars_after,
  count_total, count_withheld, include_nonlinear, include_toc_pages)`
  (`TextSearchResult`), `resolve_boundary(boundary, *, precision='item')`
  (`ResolvedBoundary`) and `position_at_percent(percent)`
  (`TextPosition`).
