# Stream 1.5: models-data

Release-notes fragment for stream 4.2 to assemble. New model fields and
properties, and tolerant date reading. No existing method's results
change on a library whose dates are valid.

## CHANGELOG

### Added

- **Book fields** (read from the library database; None where Books
  records nothing or the value doesn't convert):
  - `language` (as Books stores it, e.g. `en`), `year` (an int) and
    `release_date` (the Store release date; for an upcoming series
    volume, the expected date).
  - `series_id`, `series_container_id`, `series_sequence` (a float, e.g.
    2.0 or 2.5), `series_label` (e.g. "Book 2") and `series_is_ordered`
    (set on series containers): where a book sits in a Store series.
    Provisional, like the series API built on them.
  - `high_water_progress`: the furthest point Books recorded, in percent
    like `reading_progress`. Information only: it can be ahead of where
    you are now (after skimming ahead, for example).
- `Book.is_pdf`: whether the library records the book as a PDF, decided
  from the database alone (unlike `BookContent.is_pdf`, which looks at
  the file). New constant `py_apple_books.models.book.CONTENT_TYPE_PDF`.
- **Annotation fields**, read on bookmarks and the reading-position row
  only (None on highlights):
  - `position_fraction` and `furthest_fraction`: where the reader is and
    the furthest point read, as 0..1 fractions of the book. For a PDF,
    this is where Books records the reading position.
  - `location_data`: Books' own position record for the row, as raw
    bytes (left out of `repr`).
  - `page_location`: that record decoded as a
    `py_apple_books.models.PageLocation(ordinal, page_offset)` with
    `page` (1-based); for a PDF the page, for an EPUB bookmark without a
    CFI the spine item. `PageLocation.from_plist(data)` decodes raw
    bytes and never raises.
- `Annotation.is_short_selection`: whether a highlight is a word or a
  short phrase rather than a passage (`text.is_short_selection`); False
  for bookmarks and the reading-position row.
- `Location.end_sort_key`: the document-order key of where a range CFI
  ends (`sort_key` is where it starts), so a highlight's range can be
  compared with another location without opening the book.

### Fixed

- A date Books stored in a form that can't be read (text, NaN, infinity,
  or far outside the range a date can hold) no longer makes every list
  containing that book or annotation fail: the date reads as None. Valid
  dates convert exactly as before.
- Building a `Book` or `Annotation` from another one's fields keeps its
  dates (it raised `TypeError` before).

### Compatibility notes

- `Book` and `Annotation` have new fields, appended after the existing
  ones with default None: positional construction keeps working, but
  `repr()`, `==` and `dataclasses.fields()` include them.
- `store_info().missing_columns` lists the new fields on Books versions
  whose database lacks their columns (older versions lack
  `series_sequence` and `series_is_ordered`, for example). They read as
  None there; filtering or sorting on them raises
  `UnsupportedSchemaError`, as for every optional column. apple-books-mcp
  0.9's `--doctor` shows the list in its NOTE line.
- Books stores `position_fraction` and `furthest_fraction` as text, so a
  filter or `order_by` on them in a query compares text (`'0.10'` sorts
  before `'0.9'`); compare the float values in Python instead.
- The two fractions are read only when the row's `type` is read too: a
  query with `only=` fields that leave out `type` gets None for them.
