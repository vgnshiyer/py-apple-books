# Stream 1.2: db-robustness

Release-notes fragment for stream 4.2 to assemble. Reads and collection
writes cope with text that isn't valid UTF-8; a private slot on
`LibraryDB` for objects later 1.11 features derive from a library. No
public API change.

## CHANGELOG

### Fixed

- **(MCP)** Text that isn't valid UTF-8 in the Apple Books stores (a
  title, an author, a highlight) no longer makes every list or search
  that reads it fail with `DBQueryError`. It reads with U+FFFD (�) in
  place of the invalid bytes, and a warning is logged once per library
  (logger `py_apple_books.db`). Valid text reads exactly as before.
  Connections handed out by `LibraryDB.connection()` and
  `LibraryDB.open_connection()` still decode text as `sqlite3` does by
  default.
- **(MCP)** Error messages no longer include the text of a cell that
  isn't valid UTF-8; they name the column only.
- Collection writes no longer fail on a collection title or a book asset
  id that isn't valid UTF-8, and leave such text byte for byte as it was
  (a book's asset id is copied into the new membership row unchanged). A
  collection whose id isn't valid UTF-8 is refused like any collection
  that isn't user-created (`SystemCollectionError`). Any other invalid
  text a write would have to read stops it with `WriteError` ("nothing
  was changed"), without quoting the text. That includes the store's
  Core Data metadata, which 1.10 treated as unavailable: it wrote anyway
  with a warning under the default model check, and raised
  `SchemaValidationError` under `enforce`.
